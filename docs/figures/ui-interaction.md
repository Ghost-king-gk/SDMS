任务卡：P02 ｜ 主责：ljj ｜ 分支：`docs/ui-flow`

## 3. 总体布局

主窗口采用**左日历、右列表、底部操作**的三段式，见 `ui-wireframe-main.svg`。

| 区域 | 控件 | 职责 |
| --- | --- | --- |
| ① 日历选择区 | `calendar` 网格 + `ttk` 按钮 | 显示月历、跨月前后缀日期、切换月份、回到今天、标记有日程的日期 |
| ② 当前日期条 | `ttk.Label` | 显示当前筛选日期与当天日程条数 |
| ③ 日程列表 | `ttk.Treeview` | 三列（时间 / 标题 / 备注），每行绑定 `schedule_id`，按时间、id 确定性排序 |
| ④ 操作按钮区 | `ttk.Button` × 6 | 新增、查看、修改、删除、刷新、退出 |
| ⑤ 状态栏 | `ttk.Label` | 显示最近一次操作结果与当前选中项 |

三条布局约束：

- **行标识与显示分离**。列表显示的是格式化文本，但每一行必须关联 `schedule_id`（UUID 文本）。禁止用行号或标题反查记录——标题可重复，行号会随排序变化。
- **首次启动显示当天**。空库也要有清晰的空状态，不能是一片空白让人以为程序坏了。
- **日历必须覆盖跨月与闰年**。相邻月份的日期以灰色前缀/后缀显示但不参与本月筛选；这两个场景列入强制验收（见第 6 节 V-07）。

## 4. 六个界面状态

草图覆盖计划要求的全部六个状态。

| 状态 | 触发 | 界面表现 | 对应草图 |
| --- | --- | --- | --- |
| 列表态 | 启动 / 切换日期 / 刷新 | ③ 显示当天全部日程，② 显示条数，⑤ 显示「就绪」 | 主窗口 |
| 日历态 | 点击月份箭头、日期格、今天 | ① 重绘网格，选中格高亮，有日程的日期带标记点 | 主窗口 ① |
| 表单态 | 点击「新增」或「修改」 | 弹出 `ui-wireframe-form.svg`，四个字段，标题与预填数据不同 | 表单草图 |
| 确认态 | 选中后点击「删除」 | 模态对话框，说明将删除哪一条且不可撤销 | 对话框草图（左） |
| 错误态 | 解析失败、校验失败、写入失败 | 提示具体原因并给出可执行建议，不暴露堆栈 | 对话框草图（中） |
| 空状态 | 所选日期无记录 | 列表区显示「暂无日程」与下一步引导，② 显示「共 0 条」 | 对话框草图（右） |

**表单只有一个。** 新增与修改共用 `schedule_form.py`，差别仅在窗口标题和是否预填。禁止复制一整套创建逻辑再复制一整套编辑逻辑——那是最容易让两处行为漂移的做法。

## 5. 交互规则

以下规则来自契约草案第 4 节，UI 侧必须遵守。每条都指向一项可以被单测或人工验证的行为。

### 5.1 输入解析与校验

- 界面只负责把字符串解析成 `date` / `time`；**业务不变量由 `domain` 校验**。controller 不能替领域层做决定，领域层也不能依赖 UI 已校验才正确。
- 解析失败给出**字段级**提示，并且带上正确格式（例：`日期格式不正确，应为 YYYY-MM-DD，例：2026-10-15`）。
- 约定格式：日期 `YYYY-MM-DD`，时间 `HH:MM`，分钟精度，本地朴素时间，不处理时区。
- 标题去首尾空白后非空；备注允许为空。

### 5.2 写入成功与失败

- **写入成功后**才刷新列表并提示成功。
- 写入失败时**保留表单与已填内容**，提示失败原因。任何情况下不得假装成功。
- 只有可解释的预期错误（`ValidationError` / `ScheduleNotFound` / `StorageError`）被转换成用户提示；意外异常记录诊断信息并给通用提示，不静默吞掉，也不把裸堆栈甩给用户。

### 5.3 删除的两条路径

这是本轮最容易写错的地方，两张流程图就是为它画的。

**未选中时点击删除**（`ui-delete-flow-unselected.svg`）：controller 读到 `selected is None`，就地提示「请先选择一条日程」并返回。**整条链路零次服务调用**——未选中是界面状态问题，不是业务错误，不应当产生一条 `ScheduleNotFound`。

**选中后点击删除**（`ui-delete-flow-confirm-cancel.svg`）：

- 确认框弹出时**服务尚未被调用**。
- 点「取消」→ 对话框关闭，列表与数据不变，`service.delete` 一次都不调用。
- 点「确定」→ 才调用 `service.delete(schedule_id)`；记录是否存在由服务层校验，UI 不替它判断。
- 成功 → 刷新列表；失败 → 提示并保留原状。

删除确认属于**交互策略**，不能替代服务层的有效性校验。即便 UI 已经确认过，服务内部仍要处理记录不存在的情况。

### 5.4 选中与切换

- 无选中项时点击「修改」或「删除」，提示先选择日程，**不把 `None` 传给服务**。
- 切换筛选日期后清空选中项并刷新列表。
- 修改日期后，被修改的记录从当前列表移出是**正常行为**，不是 bug；此时刷新当前筛选日期即可。

## 6. 人工 GUI 验收步骤

自动化测不到的部分由人工验证。每条记录：操作系统版本、Python 版本、Tk 版本、前置数据、操作步骤、预期结果、实际结果、截图路径（存 `docs/screenshots/`）。截图只用虚构日程，不要把个人真实安排写进提交材料。

| 编号 | 需求 | 步骤 | 预期 |
| --- | --- | --- | --- |
| V-01 | F-01 | 启动程序 | 窗口正常显示，默认选中当天，列表与按钮齐全 |
| V-02 | F-02 | 填写完整字段后保存 | 提示成功，列表立即出现该条，表单关闭 |
| V-03 | F-02 | 标题只输入空格后保存 | 给出字段级提示，不写入，已填内容保留 |
| V-04 | F-02 | 日期填 `2026/10/15` 后保存 | 提示格式应为 `YYYY-MM-DD`，不写入 |
| V-05 | F-03 | 选择另一天 | 列表只显示当天日程，条数与标题栏一致 |
| V-06 | F-03 | 选择无任何日程的日期 | 显示空状态与「共 0 条」，不是空白或报错 |
| V-07 | F-01 | 在日历上跨月翻页，并定位到 2028-02 | 跨月前后缀日期灰显且不可选为本月；2028 年 2 月有 29 天 |
| V-08 | F-04 | 选中一条点「修改」，改标题后保存 | 列表更新，`schedule_id` 不变 |
| V-09 | F-04 | 修改日期为另一天 | 保存后该条从当前列表移出，切到新日期可见 |
| V-10 | F-05 | 未选中任何行点「删除」 | 提示先选择日程，**服务未被调用**，数据不变 |
| V-11 | F-05 | 选中后点「删除」，在确认框点「取消」 | 对话框关闭，列表与数据完全不变 |
| V-12 | F-05 | 选中后点「删除」，点「确定」 | 该条消失，条数减一 |
| V-13 | F-06 | 连续快速点击按钮、重复删除同一条 | 给出可理解提示，不出现裸堆栈，程序仍可继续操作 |
| V-14 | 工程增强 | 新增若干条后退出程序，重新启动 | 数据仍在，说明持久化生效 |

V-10 与 V-11 是界面层的**核心断言**，必须用测试替身验证「服务调用次数为 0」，不能只靠肉眼看列表没变。

## 7. 与实现文件的映射

后续 P09、P10 落地时，本文各节对应到这些文件：

| 文件（未来路径） | 承接本文 |
| --- | --- |
| `ui/controller.py` | 第 5 节全部：解析、选中态、调用用例、错误转提示 |
| `ui/presenters.py` | 显示格式化、条数文案、错误到提示的映射，尽量写成纯函数 |
| `ui/app.py` | 第 3 节布局与事件接线 |
| `ui/calendar_view.py` | 第 3 节 ①，含跨月与闰年 |
| `ui/schedule_form.py` | 第 4 节表单态，新增与修改共用 |

分层约束（违反即视为设计错误）：`ui` 不 import `sqlite3`，不拼 SQL；领域层不 import `tkinter`；服务层不弹窗；模块导入时不得创建窗口或连接数据库。

# 界面截图与环境附录

本目录保存界面的真实运行截图。每张图都在这里写明**环境、前置数据、操作步骤、预期结果、实际结果**，
使旁人可以照着复现，而不是只看到一张漂亮图（课程要求：截图要可复核）。

## 1. 运行环境（V-17 要求记录）

| 项 | 值 |
| --- | --- |
| 操作系统 | Windows 11，`Windows-11-10.0.26200-SP0` |
| Python | 3.12.14（uv 管理的解释器） |
| GUI 框架 | PySide6 **6.12.0**（Qt for Python） |
| Qt | **6.12.0** |
| 依赖安装方式 | `uv sync`（`pyproject.toml` 声明 `PySide6>=6.11.2,<7.0`，`uv.lock` 定版） |
| 目标平台 | **仅 Windows**，Linux 端不适配（见 `docs/figures/ui-interaction.md` 第 11 节） |

版本号来自本机实测而非 PyPI 页面：跑 `uv run python -c "import PySide6; print(PySide6.__version__)"`，
以及 `scripts/qt_probe.py`（Qt 版本、周起始、闰年、控件行为一并探测）。

## 2. 截图怎么复现

```bash
uv sync                 # 首次需要下载 PySide6（约 650 MB，已在缓存中则为秒级）
uv run python scripts/shoot_ui.py
```

一条命令产出本目录全部 PNG，并把 V 清单里可机器判定的部分断言掉（当前 **38 项全过**：
32 项界面回归跑在内存替身上，6 项真服务场景跑真连接 + 真 SQLite，见第 4 节）。
脚本会重新打开真实窗口逐屏截取，因此**截图与代码始终同步**——不会出现"文档里的图是上一版界面"的情况。

**必须在有显示服务的桌面会话里跑。** `QT_QPA_PLATFORM=offscreen` 下 `QFontDatabase` 返回 0 个字体，
中文会渲染成方块，那种截图没有验收价值；离屏只用于验证"窗口能否创建"这类逻辑断言。

**跑的时候请把双手从鼠标键盘上拿开。** 脚本用定时器自动点掉模态对话框（表单、确认框、日期浮层），
全程约一分钟。这期间任何物理点击都会打断自动流程——脚本对"类型不符的模态"会记一条 FAIL 而不是
挂住等人，所以万一被碰过，看输出里哪一条 FAIL 就能定位，重跑一遍即可。

模态对话框是自动走的：`ModalDriver` 用 `QTimer` 按计划依次认领弹出的模态框（表单 / 消息框 /
日期浮层）。关键时序是**先把下一拍排定、再执行当前动作**——点「选择」会同步弹出浮层并阻塞在
当前调用里，若按"动作返回后再排下一拍"写，下一拍永远排不上，整个脚本会挂死。

**诚实边界（没有假装已验）**：

- 32 项界面回归跑在**内存替身**上，验的是交互规则（不拦输入、失败保留、删除守卫），天然验不了持久化；
- 6 项真服务场景走真连接 + 真 SQLite，V-14 的真身在此——但只覆盖"经服务落盘 + 重连可读"，
  不覆盖真实用户库的迁移与损坏场景（那属于存储层单测与集成测试的职责）；
- 截图能证明"这一屏看起来对"，不能证明"换一台机器 DPI 缩放后不错位"——Windows 真机的字体、
  DPI 缩放与原生样式仍需人工在各分辨率下看一眼。

## 5. 关于 `dev_stub_service.py`

它是**开发替身**，不是真正的存储层。默认入口早已改接真 SQLite（见 README「当前状态」），
替身现在的作用是给**界面回归**提供确定、无外部依赖的运行环境：种子固定、可重复、不进磁盘，
所以第 4 节前 32 项断言跑在它上面。它实现了与真服务完全相同的 `ScheduleServicePort` 协议，
`tests/contract/test_repository_contract.py` 对内存实现与真 SQLite 跑同一套仓储契约用例，两者行为不一致会直接红。

它的 Bug 不算业务的 Bug，但它的**行为约定**（空标题怎么办、删不存在的记录怎么办）已经由
`tests/unit/test_dev_stub_service.py` 的 33 项用例锁住，与真存储的行为约定互为参照。
